# Product

## Platform

web

## Stack

Static HTML, CSS and JavaScript on a same-origin HTTPS or loopback host. No runtime packages or backend.

## Users

The primary user is a learner practicing how to read an itemized medical bill. The interface must distinguish a fictional example from personal medical or billing advice.

## Product Purpose

Make a charge, the rule that raised a question, and an appropriate next step readable on the same screen. Let another reader reproduce the calculation and print a checklist in English or Spanish.

## Capabilities and Constraints

Three fictional bills and bounded edits to their line amounts and units. A selected Medicare reference snapshot with locality inputs, not a hospital fee schedule or a claim adjudicator. No personal information, real bill upload, account, metrics collection, or claim submission. Local exports and a fresh, separately delivered key for each sealed summary.
